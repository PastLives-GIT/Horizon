vLLM v0.26.0: Inkling Support, DeepSeek-V4 Speedups, Flexible Attention 8.0

vLLM v0.26.0 introduces full support for the Inkling model family, a 975B-parameter open-weights MoE transformer, along with significant performance improvements for DeepSeek-V4 including a specialized routing kernel and fused topk bias. It also adds fp32 lm_head accuracy enhancement and allows per-KV-cache-group selection of attention backends. These improvements make vLLM a more versatile and performant serving engine, enabling efficient deployment of cutting-edge models like Inkling and DeepSeek-V4. The flexible attention backend and fp32 lm_head directly benefit hybrid models and accuracy-sensitive generation tasks, which is critical for enterprise and research use cases. The release includes 411 commits from 212 contributors, with notable items such as piecewise CUDA graph support for Inkling, a DeepSeek-V4 routing kernel yielding 2.94% E2E TPOT improvement, and Hopper FA4 relative attention. The attention backend can now be selected per KV-cache group, and sliding window is an explicit backend capability. KV offloading and tiered storage have also matured substantially.

The Inkling model family, developed by Thinking Machines Lab, is a Mixture-of-Experts transformer with 975B total parameters and 41B active, supporting up to 1M tokens context. Flexible attention backends allow vLLM to adapt to different hardware and model architectures, such as those combining sliding window and full attention.

Open-Weight AI's Kubernetes Moment: Infrastructure Standard 8.0

In a July 2026 blog post, Tobi Knaup argues that open-weight AI models are becoming the foundational infrastructure layer for AI, analogous to Kubernetes in cloud computing. This analogy highlights critical debates about the practicality of regulating open-weight models by origin, the pricing power of proprietary AI providers, and the potential for collaborative model development among companies. Open-weight models release the final weights and biases of a trained neural network, but not the training data or code, limiting modification. The Kubernetes analogy is imperfect because Kubernetes allowed source code inspection and contribution, which open-weight models do not.

Background: Open-weight models are AI models whose core components (the weights) are publicly released, allowing anyone to download and run them, but without full access to training data or code. Kubernetes is an open-source system for automating deployment, scaling, and management of containerized applications; it became the de facto standard for cloud infrastructure. The comparison suggests that open-weight models could similarly become the standard substrate for AI, influencing regulation, pricing, and collaboration.

Ruff v0.16.0 expands default rules from 59 to 413 8.0

Ruff v0.16.0, released July 23, 2026, now enables 413 linting rules by default, up from 59 in previous versions. This significant expansion will catch many more issues without any configuration. This change drastically increases the strictness of Ruff's default checks, potentially breaking many existing CI pipelines and workflows.
